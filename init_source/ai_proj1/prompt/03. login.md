# Login with Sanctum Authentication

## Backend Implementation

### 1. Laravel Sanctum Setup
- Install Laravel Sanctum package: `composer require laravel/sanctum`
- Publish Sanctum configuration: `php artisan vendor:publish --provider="Laravel\Sanctum\SanctumServiceProvider"`
- Run Sanctum migrations: `php artisan migrate`
- Add Sanctum middleware to `app/Http/Kernel.php`

### 2. Authentication Controller
Create `AuthController` with the following methods:

#### Login API
- **URI**: `POST /api/auth/login`
- **Parameters**: 
  - `email` (required, email format)
  - `password` (required, min 8 characters)
- **Response**: 
  - Success: `{ "token": "...", "user": {...} }`
  - Error: `{ "message": "Invalid credentials" }`
- **Validation**: Validate email format and password requirements
- **Authentication**: Check credentials against `users` table
- **Token**: Create personal access token using Sanctum

#### Logout API
- **URI**: `POST /api/auth/logout`
- **Headers**: `Authorization: Bearer {token}`
- **Response**: `{ "message": "Successfully logged out" }`
- **Action**: Revoke current access token

#### User Profile API (Protected)
- **URI**: `GET /api/auth/user`
- **Headers**: `Authorization: Bearer {token}`
- **Response**: Current authenticated user data
- **Guard**: `auth:sanctum`

### 3. Route Protection
- **API Guard**: `auth:sanctum`
- **Protected Routes**: Apply middleware to routes requiring authentication
- **Route Groups**: Group protected routes under `auth:sanctum` middleware

### 4. CORS Configuration
- Configure CORS for frontend domain
- Allow credentials for cookie-based authentication (if needed)

## Frontend Implementation

### 1. Login Form
- Create login form with email and password fields
- Add form validation (email format, required fields)
- Handle form submission with API call

### 2. Token Management
- Store authentication token securely (localStorage/sessionStorage)
- Add token to HTTP headers for authenticated requests
- Implement token refresh mechanism if needed

### 3. Authentication State
- Create authentication store/context
- Manage login/logout state
- Redirect logic for protected routes

### 4. HTTP Interceptors
- Add request interceptor to include token in headers
- Add response interceptor to handle 401 unauthorized responses
- Automatic logout on token expiration

## Error Handling
- Invalid credentials (401)
- Validation errors (422)
- Token expiration (401)
- Network errors
- Rate limiting (429)

## Security Considerations
- CSRF protection
- Rate limiting for login attempts
- Password hashing (bcrypt)
- Token expiration
- Secure token storage
- Input sanitization Sanctum
